## Confirmed and static failures

### P0

- SEC-001 (static_analysis, high): A turn or tool call without threadId can query and consume pending background results for the target agent across all conversations and resources.
- SEC-002 (static_analysis, high): A direct metaAgent.generate call that supplies a thread but omits resource uses the constant resource meta-agent while Meta working memory is resource-scoped by default.
- MEM-001 (observed, high): One persisted thread accepted messages from two different resources instead of rejecting the resource mismatch.

### P1

- RES-001 (observed, high): Prose, malformed JSON, invalid status, and empty input normalize to status ok; empty delegation result strings bypass wrapper validation.
- CAN-001 (static_analysis, high): The common tool envelope drops Mastra ToolExecutionContext, including abortSignal and request/runtime context, before calling the wrapped implementation.
- CAN-002 (static_analysis, high): A synchronous pipeline delegation timeout rejects only the caller wait; the underlying agent.generate receives no AbortSignal and can continue.
- CAN-003 (unknown, high): A pre-aborted direct generate was not rejected and persisted a user message.
- DUR-001 (static_analysis, high): Async delegation persists a running record but executes the attempt as an unawaited promise in the request process; no recovery/claim worker for async_delegations is present.
- IDN-001 (observed, high): Two overlapping harness attempts with the same taskId and no runId collapsed into one runtime run identity and one run row.
- BUD-001 (static_analysis, high): The harness deadline is enforced only around the first agent.generate; optional repair/review/deliberation/approval/completion passes can call the model without timeout or AbortSignal.

### P2

- EVT-001 (static_analysis, high): Async completion queues a pending message but does not autonomously re-enter the front agent; delivery waits for another user turn or explicit polling.
- HRN-001 (static_analysis, high): Meta root harness wraps generate only; stream and streamUntilIdle retain original Agent implementations.
- HRN-002 (static_analysis, high): Pipeline agents use a lightweight reflection wrapper around bare agent.generate and bypass the full shared harness.
- AGT-001 (unknown, medium): Ten Agent Board targets completed isolated no-tool local-provider smoke calls with empty response text in two separate runs.
- TST-001 (observed, high): The intended npx tsx path could not start temporary TypeScript tests.

## Observations

- Same-thread cross-resource writes, pre-abort persistence, and same-task run-ID collapse are dynamically observed.
- Ten Board agents returned empty text in two local repeats; the causal layer is unknown.
- Static inspection establishes multiple execution gateways, generate/stream and pipeline harness gaps, next-turn polling delivery, and same-process async execution.

## Inferences

- The current execution surfaces cannot be treated as one behavioral contract; migration risk is path-dependent.
- Empty results can combine model/runtime behavior with ResultEnvelope false-success semantics; the empty-agent observation alone does not localize the defect.
- A durable target will require a canonical attempt identity and scoped inbox/outbox, inferred from the observed collision and static routing gaps.

## Architecture constraints

- Identity must fail closed: tenant/resource/conversation/thread/job/run/attempt must be explicit and immutable across every route.
- One channel-independent execution gateway must enforce aggregate deadlines, propagated cancellation, GoalContract and honest terminal ResultEnvelope semantics.
- Accepted background work must be durably claimed, leased, renewed and fenced; terminal result plus delivery intent must be atomic or outbox-backed.
- Completion must wake only the owning conversation, be deduplicated, and reject stale attempts; no unscoped pending consume fallback is admissible.
- Migration gates must include direct, stream, delegation, pipeline, workflow and scheduled paths, plus failure injection at every persistence boundary.

All architecture constraints above are inferred from this baseline; they are not an implementation plan.
