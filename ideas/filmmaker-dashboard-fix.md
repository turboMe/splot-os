## 1. Background — how files actually flow (the audit result)

Filmmaker generates videos from the user's OWN photos (I2V / FLF2V / R2V / V2V). The single paid choke point is `film_generate` (`src/mastra/tools/film/film-generate.ts`). Generated MP4s are written by `outputDirFor()` and recorded in MongoDB `agentforge.film_generation_runs.video_path`. The dashboard reads them back through `workspace-service.ts`.

### The core bug: write-root ≠ read-root

| Side | Function | Resolves `film-work` against | Result |
|---|---|---|---|
| WRITE (generation) | `film-generate.ts` `outputDirFor()` (line ~137) | `process.cwd()` of the running server = `src/mastra/public` | `src/mastra/public/film-work/` ✅ real videos land here |
| READ (dashboard guard) | `workspace-service.ts` `filmOutputRoot()` (line 759) | `AGENTIC_AGENTS_REPO` (`<repo>`) | `<repo>/film-work/` ❌ no real videos here |

`safeFilmAssetPath()` (line 766) only accepts paths **inside** `filmOutputRoot()`. All agent-generated videos live in `src/mastra/public/film-work` → guard returns `null` → `videoUrl=undefined`, `hasVideo=false` → dashboard shows "Ten projekt nie ma jeszcze pobranego MP4."

**Why one video plays:** the only MP4 under `<repo>/film-work` is an old T2V smoke test (`<repo>/film-work/codex-fal-smoke-2026-06-21T18-49-59-929Z/film-run-6daa989a-...mp4`, generated by a CLI script with cwd=repo root). It passes the guard. The 3 real I2V videos in `src/mastra/public/film-work/` are all rejected.

### Ground-truth snapshot at audit time (MongoDB `agentforge`)

4 runs have a `video_path`:
- `film-run-744eda56...` I2V → `src/mastra/public/film-work/film-run-744eda56-...mp4` (rejected by guard)
- `film-run-9caadbc...` I2V → `src/mastra/public/film-work/film-run-9caadbcd-...mp4` (rejected)
- `film-run-d6b478e...` I2V → `src/mastra/public/film-work/film-run-d6b478ea-...mp4` (rejected)
- `film-run-6daa989...` T2V → `<repo>/film-work/codex-fal-smoke-.../film-run-6daa989a-...mp4` (✅ passes — the "first video")

Three physical directories exist (do NOT confuse them):
- `<repo>/film-work/` — only the smoke test + `_inbox/`
- `src/mastra/public/film-work/` — the 3 real I2V MP4s + `_inbox/` (input-photo copies)
- `src/mastra/public/film-output/golden-hour-canyon/` — `design_generate_image` reference PNGs (unrelated)

### The "copies"

`AttachmentPersistProcessor` (`src/mastra/processors/attachment-persist.ts`, line 146) saves each user-attached photo to `film-work/_inbox/<threadId>/<sha1>.<ext>` on every turn that carries the attachment. Dedup is by content-hash filename **within a single thread dir only**, NOT across threads. Each meta→filmmaker delegation / retry creates a new `threadId` → a new directory with an identical copy. Audit found 6+ identical copies of the same JPG (md5 `2a3fb3eb...`). These are input material (harmless, but they accumulate).

### Ordering

- Runs: `FilmService.listGenerationRuns` sorts `created_at: -1` (newest first).
- Projects: `listFilmProjects` → `listProjects` sorts `updatedAt:-1, createdAt:-1`.
- The "wrong order" symptom is a side effect of the root bug: because almost every run has `hasVideo=false`, the dashboard's `selectedRun` falls through to `runs[0]` (often a no-video / rejected run), so the visible selection doesn't match expectation.

### Where input photos are stored (for the preview feature)

Each project's `state.reference_registry[]` holds the absolute path, e.g.:
```
reference_registry: [{ tag:"@Image1", role:"first_frame", path:".../public/film-work/_inbox/<uuid>/<sha1>.jpg", ... }]
```
`getFilmProjectBundle` already exposes this as `bundle.references` (line 866). One legacy entry (project `restaurant-table-i2v-001`) has a path missing the leading slash (`projekty/...`) — normalize when building the URL.

## 2. Task 1 — Fix the write-root ≠ read-root mismatch (CRITICAL, unblocks all video playback)

**File:** `src/mastra/services/workspace-service.ts`

**Goal:** make `safeFilmAssetPath()` accept the directory where videos are actually written (`src/mastra/public/film-work`), while staying a real sandbox (reject arbitrary paths / traversal).

**Current code (lines 759–772):**
```ts
function filmOutputRoot(): string {
  const configured = process.env.FILM_OUTPUT_DIR || 'film-work';
  if (path.isAbsolute(configured)) return path.resolve(configured);
  const repoRoot = process.env.AGENTIC_AGENTS_REPO || '/projekty/mastra-agentic-environment/agentic-agents';
  return path.resolve(repoRoot, configured);
}

function safeFilmAssetPath(filePath: string | undefined): string | null {
  if (!filePath) return null;
  const root = filmOutputRoot();
  const resolved = path.isAbsolute(filePath) ? path.resolve(filePath) : path.resolve(process.cwd(), filePath);
  if (resolved === root || resolved.startsWith(root + path.sep)) return resolved;
  return null;
}
```

**Change:** replace the single root with a LIST of allowed roots, and accept a path inside ANY of them. Allowed roots:
1. `process.env.FILM_OUTPUT_DIR` resolved against `process.cwd()` (the actual write location at runtime).
2. `<repoRoot>/film-work` (legacy smoke-test location — keep so the old T2V video still plays).
3. `<repoRoot>/src/mastra/public/film-work` (explicit, in case cwd differs).
4. `<repoRoot>/src/mastra/public/film-output` (design reference PNGs — needed for Task 3 if refs ever point here; harmless to include).

**Proposed implementation:**
```ts
function filmAssetRoots(): string[] {
  const roots = new Set<string>();
  const repoRoot = process.env.AGENTIC_AGENTS_REPO || '/projekty/mastra-agentic-environment/agentic-agents';
  const configured = process.env.FILM_OUTPUT_DIR || 'film-work';
  // 1) configured, resolved against the SERVER cwd (where outputDirFor actually writes)
  roots.add(path.isAbsolute(configured) ? path.resolve(configured) : path.resolve(process.cwd(), configured));
  // 2) configured against repo root (legacy CLI/smoke-test location)
  if (!path.isAbsolute(configured)) roots.add(path.resolve(repoRoot, configured));
  // 3) the real runtime output dir (server cwd = src/mastra/public)
  roots.add(path.resolve(repoRoot, 'src/mastra/public/film-work'));
  // 4) design reference frames
  roots.add(path.resolve(repoRoot, 'src/mastra/public/film-output'));
  return [...roots];
}

function safeFilmAssetPath(filePath: string | undefined): string | null {
  if (!filePath) return null;
  // normalize legacy paths missing a leading slash (e.g. "projekty/...") to absolute
  const candidate = !path.isAbsolute(filePath) && filePath.startsWith('projekty/')
    ? '/' + filePath
    : filePath;
  const resolved = path.isAbsolute(candidate) ? path.resolve(candidate) : path.resolve(process.cwd(), candidate);
  for (const root of filmAssetRoots()) {
    if (resolved === root || resolved.startsWith(root + path.sep)) return resolved;
  }
  return null;
}
```
Keep `filmOutputRoot()` if other code references it, or delete if unused (grep first: `grep -n filmOutputRoot src/mastra/services/workspace-service.ts`).

**Why this is safe:** still a whitelist of known dirs under the repo; rejects traversal and arbitrary FS reads. It just widens to the dir videos truly live in.

**Verification:**

- Query the bundle for a project with an I2V video and confirm `runs[].videoUrl` is now set:

- After server restart: GET `/ws/filmmaker/projects/<id>` → runs with real videos now have `videoUrl` and `hasVideo:true`. GET `/ws/filmmaker/runs/<runId>/video` returns the MP4 (200/206) instead of 404.

```ts
export async function getFilmReferenceImagePath(projectId: string, tag: string): Promise<string | null> {
  const film = new FilmService();
  const project = await film.getProject(projectId);
  const refs = project?.state?.reference_registry ?? [];
  const ref = refs.find((r: any) => r.tag === tag);
  return safeFilmAssetPath(ref?.path);  // sandbox guard (now incl. _inbox under public/film-work via Task 1)
}
```

**New route** (content-type by extension; images are small, no range needed):
```ts
registerApiRoute('/ws/filmmaker/projects/:id/reference', {
  method: 'GET',
  handler: async (c: any) => {
    try {
      const u = new URL(c.req.url, 'http://localhost');
      const tag = u.searchParams.get('tag') || '';
      const ws = await import('./services/workspace-service.js');
      const fs = await import('node:fs/promises');
      const p = await ws.getFilmReferenceImagePath(c.req.param('id'), tag);
      if (!p) return c.text('Reference image not found', 404);
      const ext = p.toLowerCase().endsWith('.png') ? 'image/png'
        : p.toLowerCase().endsWith('.webp') ? 'image/webp' : 'image/jpeg';
      const buf = await fs.readFile(p);
      return c.body(buf, 200, { 'Content-Type': ext, 'Cache-Control': 'private, max-age=300' });
    } catch (err) {
      return c.text((err as Error).message, 500);
    }
  },
}),
```

## 5. Task 4 — Delete filmmaker projects from the dashboard

Goal: a delete button per project card so the user can remove excess project entries (and their runs, optionally their files).

### 5a. Service + route

**Service function** in `workspace-service.ts`:
```ts
export async function deleteFilmProject(projectId: string, opts: { deleteFiles?: boolean } = {}): Promise<{ deletedRuns: number; deletedFiles: number }> {
  const db = await getDb();
  // gather video paths first if we will delete files
  let deletedFiles = 0;
  if (opts.deleteFiles) {
    const runs = await db.collection<FilmGenerationRun>('film_generation_runs')
      .find({ project_id: projectId }).toArray();
    const fs = await import('node:fs/promises');
    for (const r of runs) {
      const safe = safeFilmAssetPath(r.video_path);
      if (safe) { try { await fs.unlink(safe); deletedFiles++; } catch {} }
    }
  }
  const runRes = await db.collection('film_generation_runs').deleteMany({ project_id: projectId });
  await db.collection('film_projects').deleteOne({ id: projectId });
  // also remove any approvals tied to the project (optional, keeps the Approvals tab clean)
  await db.collection('approvals').deleteMany({ 'args.projectId': projectId }).catch(() => {});
  return { deletedRuns: runRes.deletedCount ?? 0, deletedFiles };
}
```
> Check the exact collection names / `FilmService` API before writing — there may already be a `FilmService.deleteProject`. Grep: `grep -n "deleteProject\|deleteOne\|deleteMany" src/mastra/tools/film/film-service.ts`. Reuse the service layer if it exists rather than touching collections directly.

**Route** in `src/mastra/index.ts` (near the other filmmaker routes):
```ts
registerApiRoute('/ws/filmmaker/projects/:id', {
  method: 'DELETE',
  handler: async (c: any) => {
    try {
      const u = new URL(c.req.url, 'http://localhost');
      const deleteFiles = u.searchParams.get('files') === '1';
```

## 6. Task 5 — De-duplicate / clean `_inbox` copies (optional, lowest priority)

Goal: stop accumulating identical photo copies and/or provide cleanup.

**File:** `src/mastra/processors/attachment-persist.ts` (line ~146, `baseDir = 'film-work/_inbox'`, then `outDir = .../<threadSeg>`, hash-named file at line 169–171).

Two options (pick one with the user; this is an optimization, NOT a blocker):

**Option A — content-addressed store (preferred):** write to `film-work/_inbox/by-hash/<sha1>.<ext>` instead of `<threadId>/<sha1>.<ext>`. Same photo across threads → same file, no duplication. Caveat: the path is then shared, so `reference_registry` entries across projects may point to one file — fine for read-only input material. Requires verifying nothing relies on the per-thread directory.

**Option B — cleanup script / endpoint:** leave the processor as-is, add a maintenance script `src/mastra/scripts/clean-film-inbox.ts` that removes `_inbox/<uuid>` dirs not referenced by any project's `reference_registry`. Run manually.

**Recommendation:** Option A for the real fix; defer if the user only cares about playback. Do NOT change the absolute-path contract that `film_generate.referenceValue()` and `AttachmentPersistProcessor` rely on (paths must stay absolute and inside an allowed sandbox).

**Verification:** attach the same photo twice in two delegations → only one file on disk (Option A); existing projects still resolve their `reference_registry` paths.
